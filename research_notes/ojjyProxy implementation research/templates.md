## The templates are 2.x direct-transport examples, but not the newest pair

The vendored controller bundle exposes **VERSION `0.0.13`** and asserts the core must be exactly **`2.0.67-alpha.1`**. The core bundle also contains that alpha.1 version string. The controller uses the separately loaded `$scramjet` runtime, direct transport, generated controller/frame prefixes, and persisted `__scramjet_controller` cookies. Thus these templates are **not Scramjet 1.1.0/Bare-Mux examples**, even though their styling is simple and the HTML needs no compilation. ([Exact bundled controller](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/templates/html/2.0.67-alpha.1/controller/controller.api.js); [bundled core](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/templates/html/2.0.67-alpha.1/scramjet/scramjet.js)).

Contrast with [engines.md](engines.md) and [networking.md](networking.md): those notes identify current core **2.0.67-alpha.2/controller 0.0.14**, used in InvisiProxy production/master, while soap/soap-rewrite resolve alpha.1/0.0.13. The new templates therefore corroborate **the soap-era API generation**, not a newer upgrade. Copying only a newer core or only a newer controller will violate the exact-version assertion. The generated `.mjs` external stub re-exports the previously installed global controller; it does not bootstrap that global independently. ([Stub](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/templates/html/2.0.67-alpha.1/controller/controller-external.mjs); [current pair registry evidence](https://registry.npmjs.org/@mercuryworkshop%2fscramjet/2.0.67-alpha.2)).

## Setup, transport, scope and build lessons

HTML loads classic scripts in order: `/scramjet/scramjet.js`, `/controller/controller.api.js`, and CDN **`@mercuryworkshop/epoxy-transport@3.0.1/dist/index.js`**. It takes `self.EpoxyTransport.default`, constructs it with **`wss://wisp.mercurywork.shop/`**, awaits `transport.init()`, creates `Controller`, awaits `scramjet.wait()`, then binds a frame. This is source-level integration evidence for that generation, not confirmation that the public relay is available or that the CDN distribution works in every browser. No Bare-Mux is loaded, and no relay is included. Vendor transport locally and configure an owned relay in ojjyProxy. ([HTML source](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/templates/html/2.0.67-alpha.1/index.html)).

Both workers import `/controller/controller.sw.js` and selectively use `$scramjetController.shouldRoute(e)`/`route(e)`. HTML registers `/sw.js`, waits for `navigator.serviceWorker.ready`, and selects the controlling worker or registration's active worker. The registration promise has no rejection catch outside `init`, and readiness has no explicit control timeout. Root placement is a template convention; **a namespaced worker can use a matching narrower scope and adjusted asset/prefix config**. Do not treat README “MUST be served from your site root” as a universal API limitation. ([HTML worker](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/templates/html/2.0.67-alpha.1/sw.js); [React worker](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/templates/react/2.0.67-alpha.1/public/sw.js); [MDN scope](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register)).

The HTML README documents localhost/HTTPS, real WASM MIME, exact default runtime/inject paths, static serving with **`bunx serve .`**, **`python3 -m http.server 3000`**, or **`npx serve .`**, and CDN curl replacement of alpha.1 core JS/WASM. These are documented commands, not commands executed here. No server header configuration implements COOP/COEP; a generic static-server command alone does not establish cross-origin isolation for shared-memory-dependent features. ([HTML setup guide](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/templates/html/2.0.67-alpha.1/README.md)).

React's documented command pins **only the core**: `bun add @mercuryworkshop/scramjet@2.0.67-alpha.1 @mercuryworkshop/scramjet-controller @mercuryworkshop/epoxy-transport`. Controller and transport float; given today's controller 0.0.14 exact alpha.2 assertion, it is not a reproducible matched alpha.1 install. The guide mentions optional libcurl/utils and `vite-plugin-static-copy`, but there is no checked-in Vite configuration or build command. Runtime files must be copied into public, including controller API loaded from entry HTML. The placeholder component relay is `wss://domain.tld/wisp/`. The linked `wisp-server-node` is an unverified link in this new source; it does not supersede the concrete backend verification in networking.md. ([React setup guide](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/templates/react/2.0.67-alpha.1/README.md)).

## License and final synthesis impact

The root LICENSE is **GNU AGPL version 3** text, not MIT. No package manifest/SPDX declaration establishes an additional only-versus-later choice for this template application. ([LICENSE](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/LICENSE); [attribution request](https://github.com/x8rr/scramjet-templates/blob/ab246887ba1003add1cd3e178d157b79e0f6a7f4/README.md)).

**Recommendation:** borrow the minimal explicit initialization sequence and complete HTML asset inventory, then build the new shell against the matched alpha.2/0.0.14 pair already recommended in the six notes. Neither template adds UV, search, bookmarks, multi-tabs, history, isolation headers, Deno deployment or complete error/reconnect handling. This finding strengthens the case for a deliberate adapter architecture rather than treating a template as the finished ojjyProxy project. All source discrepancies above are inspection findings, not reproduced runtime failures.
