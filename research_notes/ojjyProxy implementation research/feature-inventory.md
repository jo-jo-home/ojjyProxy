Research date: 2026-10-12. **Research only; no app implementation.** All six supplied source ZIPs were inspected without modifying them. Selected first-party source was extracted only into the checked, preapproved temporary directory `/var/folders/d1/1ykss2fs7_v0nx_r_8qd0_9c0000gn/T/opencode/ojjy-feature-inventory/`; packaged games, generated proxy bundles and unrelated vendor libraries were not treated as proxy-shell features. The hub's clean source checkout at the recorded SHA was inspected for blue-theme and persistence reuse. The Epoxy site's actual deployed JavaScript bundle was fetched, as well as its readable upstream source. No browser rendering or network-proxy runtime tests were performed.

Status vocabulary: **wired** = UI plus an implementation/handler exists; **partial** = limited implementation or an identifiable gap; **placeholder** = markup/comment without a working feature path; **legacy-specific** = depends on an older backend/runtime; **proposal** = desired ojjyProxy addition, not a discovered existing feature. Wired does not mean runtime-tested. Negative findings mean “not found in the inspected first-party shell/router,” not proof that no third-party engine contains an internal API.

## 1. What user-facing features actually exist in each source?

### Takeaway
The real reusable union is an omnibox-driven, framed browser with engine/transport choices, search suggestions, launch shortcuts, persistent local settings, themes, tab appearance, conditional routing options, ad-filter hooks, and diagnostics. True in-app tabs, a working bookmark library, an application browsing-history library, sidebar panels, full inspector tooling and account-backed proxy persistence require new work rather than copying named menus. - Standalone proxy origin plus hub launcher/card first; match visual tokens while keeping origin-specific state separate. Optional theme handoff can pass a small validated theme ID or exported color set; it is not SSO. Later SSO requires an explicit scoped handoff and server validation, not copying a long-lived hub token into every proxied navigation. Wisp backend remains a separately suitable host. [Hub integration research](deno-hub.md); [H validated session][H-session]; [networking notes](networking.md)

#### K. Proposed delivery phases and acceptance gates

| Phase | Deliverables | Meaningful acceptance criteria |
|---|---|---|
| **1 — coherent browser foundation** | Blue shell/start screen, real app tabs, canonical omnibox, five-provider registry, SJ/UV adapters, shared validated connection settings, navigation/load/error states, local preferences, capability panel | Multiple tabs navigate independently; URL updates do not overwrite editing; back/forward stays within intended tab; cold worker/transport failures are actionable; pinned JS/WASM/header-compatible assets match; normal desktop/mobile browsing and destination WSS exercised. |
| **2 — durable everyday UX** | Bookmarks/history/sidebar/quick tiles, session restore/private-history option, JSON import/export, system/light/nord themes, reduced motion, explicit fullscreen and new real-browser-window actions | Bookmark CRUD/import roundtrip; retention/private-tab rules hold; restoration is per-tab and lazy; popup-blocked behavior works; no duplicate IDs/theme class conflicts; keyboard/mobile navigation usable; storage failure doesn't crash startup. |
| **3 — filtering and tools** | Correct normalized blocker, per-site controls/optional cosmetics; Epoxy-inspired request/response/traffic diagnostics; sandboxed Playground; inspector proof if desired | ABP/plain list fixtures match correctly; early loading policy explicit; engine reload/filter toggle reflects actual state; request cancellation/out-of-order typing bounded; trace buffer bounded; inspector targets the page and cleans up rather than inspecting only shell. |
| **4 — hub/account and optional operator features** | Hub app launcher/theme handoff, explicit account-backed preferences/bookmarks if desired; configured mirrors/region/Tor; legacy app links | Hub worker/offline games/auth unaffected; proxy origin separation preserved; sync handles reconnect/account switch/deletion; private URL data is not published in game profile; no nonexistent regions/mirrors offered; hosting assumptions verified. |

The phases prioritize a functional superset without excluding useful legacy ideas. Full native-extension support, transparent private-cookie isolation, DRM/WebRTC/HTTP3 guarantees, universally compatible CAPTCHA, automatic website offline cloning, public Twisp terminals and old external proxy services are **not established capabilities** and should not appear as completed features. Engine/network limitations and deployment prerequisites are expanded in [engines.md](engines.md), [networking.md](networking.md) and [deno-hub.md](deno-hub.md).

### Gaps
- Blueprint is implementation-ready specification direction, not validated runtime architecture. Per-tab history APIs, target-title/icon event reliability, UV raw-header bridge, shared transport mutation scope, private storage isolation and inspector injection need focused proofs against pinned versions.
- Exact hub appearance is source-grounded, but no final-project mockup/render was made. Contrast, mobile measurements, fullscreen/embedding and browser-reserved shortcuts require real UI tests.
- Optional account/userscript/legacy-app scope is not confirmed by user-facing implementation evidence; phases deliberately mark these as additions rather than inherited features.
